# CollisionGrid Class Documentation

## Overview

The `CollisionGrid` class provides a comprehensive grid-based collision detection and pathfinding system. It supports multiple collision layers, allowing for complex environment interactions and movement validation across different types of obstacles.

```gml
/// @brief A Collision Grid system for managing object collision layers.
/// This constructor initializes a grid-based collision detection system, allowing for pathfinding
/// and movement validation across multiple layers of collision objects.
function CollisionGrid() constructor {
    // Properties and methods defined...
}
```

## Properties

- **grids** (Array): Stores multiple mp_grids, each representing a separate collision layer
- **layerCount** (Real): Tracks the number of collision layers currently managed
- **position** (Struct): Defines the grid's position and dimensions:
- **x, y**: The starting coordinates of the grid (defaults to -10, -10)
- **w, h**: The width and height of the grid (defaults to room size plus padding)
- **dx, dy**: The cell size of the grid (defaults to 16x16 pixels)

## Usage Examples

### Creating and Initializing the System

```gml
// Create a collision grid system in a controller object
function create() {
    // Create the collision grid
    collision_system = new CollisionGrid();
    
    // Define collision layers (objects that represent different types of obstacles)
    collision_layers = [
        obj_wall,          // Layer 0: Solid walls (impassable for all entities)
        obj_water,         // Layer 1: Water (impassable for ground units)
        obj_low_obstacle   // Layer 2: Low obstacles (impassable for certain entities)
    ];
    
    // Initialize the collision system with the defined layers
    collision_system.reset(collision_layers);
}
```

### Room Transition Management

```gml
// Reset collision grid when changing rooms
function room_start() {
    // Define collision layers for the new room
    var layers = [
        obj_wall,
        obj_water,
        obj_low_obstacle
    ];
    
    // Reinitialize the collision system for the new room
    collision_system.reset(layers);
}
```

### Different Collision Layers for Different Entities

```gml
// Move different entities according to their movement capabilities
function move_units() {
    // Ground units can't move through walls or water
    with (obj_ground_unit) {
        var move_x = lengthdir_x(speed, direction);
        var move_y = lengthdir_y(speed, direction);
        
        // Check both wall and water layers
        if (collision_system.grid_position_is_free(0, x + move_x, y) && 
            collision_system.grid_position_is_free(1, x + move_x, y)) {
            x += move_x;
        }
        if (collision_system.grid_position_is_free(0, x, y + move_y) && 
            collision_system.grid_position_is_free(1, x, y + move_y)) {
            y += move_y;
        }
    }
    
    // Flying units only avoid walls
    with (obj_flying_unit) {
        var move_x = lengthdir_x(speed, direction);
        var move_y = lengthdir_y(speed, direction);
        
        // Only check wall layer
        collision_system.move_object(0, id, move_x, move_y);
    }
}
```

### Pathfinding for NPCs

```gml
// Set a path for an NPC to follow
function find_path_to_player() {
    // Create a path resource
    if (!path_exists(path)) {
        path = path_add();
    }
    
    // Get player position
    var player = instance_find(obj_player, 0);
    if (player == noone) return false;
    
    // Based on the unit type, use the appropriate collision layer
    var layer_id = is_flying ? 0 : 0; // Flying units only avoid walls, ground units would check layer 0 and 1
    
    // Try to find a path to the player
    var success = collision_system.grid_set_path(layer_id, path, id, player.x, player.y);
    
    if (success) {
        // Start following the path
        path_start(path, movement_speed, path_action_stop, true);
        return true;
    } else {
        // No path found
        path_delete(path);
        path = -1;
        return false;
    }
}
```

### Validating Positions for Object Spawning

```gml
// Spawn items only in valid positions
function spawn_item(item_type, room_area) {
    var attempt = 0;
    var max_attempts = 50;
    var valid_position = false;
    var spawn_x, spawn_y;
    
    // Try to find a valid spawn location
    while (!valid_position && attempt < max_attempts) {
        // Generate random position within the specified area
        spawn_x = random_range(room_area.x1, room_area.x2);
        spawn_y = random_range(room_area.y1, room_area.y2);
        
        // Check if this position is free in all relevant collision layers
        valid_position = collision_system.grid_position_is_free(0, spawn_x, spawn_y) && 
                        collision_system.grid_position_is_free(1, spawn_x, spawn_y) &&
                        collision_system.grid_position_is_free(2, spawn_x, spawn_y);
        
        attempt++;
    }
    
    // Spawn the item if a valid position was found
    if (valid_position) {
        instance_create_layer(spawn_x, spawn_y, "Items", item_type);
        return true;
    }
    
    return false; // Failed to find a valid position
}
```

## Technical Implementation Notes

1. **Multi-layer Collisions**: The system supports different collision layers for various types of obstacles or terrain, allowing entities to interact differently based on their capabilities.

2. **Memory Management**: The `reset` function properly destroys old mp_grids before creating new ones, preventing memory leaks during room transitions or level reloads.

3. **Cell-based Approach**: The grid uses a cell-based division of the room space, with customizable cell size for balancing precision and performance.

4. **Room Size Adaptation**: The grid automatically adapts to the current room size, adding a small padding to ensure proper collision detection near room boundaries.

5. **Performance Optimization**: By dividing collision detection into distinct layers, the system allows for more efficient checks tailored to specific entity types.

6. **GameMaker Integration**: The class leverages GameMaker's built-in mp_grid functions for pathfinding and collision detection, ensuring good performance and compatibility.

7. **Separate Axis Movement**: The `move_object` method implements separate axis movement checks, allowing entities to slide along obstacles rather than getting completely stuck.
